# check - 检查蓝图一致性

## 目标

检查蓝图与代码是否一致，识别是否存在架构漂移、说明缺失或方法描述过期。

## 执行步骤

### 1. 识别需要检查的范围

确定检查范围：
- 如果指定了文件或目录，只检查该范围
- 如果未指定，检查本次会话中修改的所有代码文件
- 列出所有需要检查的代码文件

### 2. 验证蓝图文件存在性

检查每个代码文件是否有对应的蓝图：
- 代码文件 `src/auth/auth.service.ts` → 蓝图文件 `.blueprint/src/auth/auth.service.md`
- 记录缺失的蓝图文件
- 记录孤立的蓝图文件（代码已删除但蓝图仍存在）

### 3. 对比代码与蓝图内容

对于每个代码-蓝图对：
- 读取代码文件，提取关键信息：
  - 类/模块名称
  - 方法/函数列表
  - 方法签名（参数、返回值）
  - 依赖关系（import 语句）
- 读取蓝图文件，提取关键信息：
  - 蓝图中描述的方法单元
  - 蓝图中描述的依赖关系
- 对比差异：
  - 代码中存在但蓝图中缺失的方法
  - 蓝图中存在但代码中已删除的方法
  - 方法签名不一致（参数、返回值变化）
  - 依赖关系不一致

### 4. 检查蓝图元数据完整性

验证蓝图文件的结构：
- 检查 Metadata 是否完整（title、type、summary）
- 检查方法单元是否包含必要字段（location、purpose、input、output、core_steps）
- 检查变更记录是否存在

### 5. 生成检查报告

输出详细的检查报告：
- 一致性状态（通过/警告/失败）
- 缺失的蓝图文件列表
- 孤立的蓝图文件列表
- 内容不一致的详细列表
- 元数据不完整的蓝图列表
- 修复建议

## 使用时机

- 任务结束前
- 提交代码前
- 需要确认蓝图是否仍可信时
- 定期审查蓝图质量时

## 检查规则

### 严重问题（必须修复）

- 代码文件存在但蓝图文件缺失
- 蓝图中的方法在代码中已删除（架构漂移）
- 蓝图元数据缺失（title、type、summary）

### 警告问题（建议修复）

- 代码中新增方法但蓝图未更新
- 方法签名变化但蓝图未同步
- 依赖关系变化但蓝图未更新
- 变更记录超过 30 天未更新

### 可忽略问题

- 代码格式化差异
- 注释变化
- 私有方法/内部实现细节

## 注意事项

- 检查不应该阻塞工作流，只提供建议
- 关注架构意图层面的一致性，不是代码细节
- 允许合理的滞后（小的重构不需要立即同步蓝图）
- 如果发现大量不一致，建议重新运行 `/claude-shadow-context:init`
