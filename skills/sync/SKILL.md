# sync - 同步影子蓝图

## 概述

`sync` 只同步会影响理解和后续修改的变化，不做全量重写。

单文件蓝图继续以蓝图模板（参考 init skill）为准，但不是所有文件都必须补满”关键方法单元”。

## 执行步骤

1. 识别本轮真正有意义的代码改动，跳过格式化和纯机械调整。
2. 映射对应蓝图路径；缺蓝图时明确标记为待补建。
3. 判断同步深度：普通文件轻量同步，核心业务文件重点同步。
4. 普通文件优先更新 `Metadata`、职责摘要和变更记录。
5. 核心业务文件按实际变更更新关键方法单元，包括 `purpose`、`input`、`output`、`core_steps`。
6. 处理新增、删除、重命名带来的蓝图结构变化。
7. 输出同步结果，并提示是否需要继续执行 `/bluefirst-plugin:check`。

## 规则

- 同步业务含义，不同步实现噪音
- 不因为模板里有“关键方法单元”就强行所有文件都填写
- 路径映射要稳定，保持镜像结构可信
- 历史蓝图过旧时，优先修正核心职责和关键方法

## 输出结果

- 已同步的蓝图文件
- 轻量同步与重点同步的区分
- 新增、修订或移除的关键方法单元
- 仍缺失的蓝图路径
